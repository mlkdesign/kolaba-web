# kolaba — мобильный веб-прототип

Прототип kolaba, собранный как самостоятельное мобильное веб-приложение: открывается
на телефоне во весь экран, листается пальцем, ставится на домашний экран.

**Демо:** https://mlkdesign.github.io/kolaba-web/

Никакой сборки и зависимостей: открытый `index.html` работает сразу, GitHub Pages
отдаёт файлы как есть.

## Запуск локально

```bash
python3 -m http.server 8000
```

и открыть http://localhost:8000/ — модули (`<script type="module">`) требуют
`http://`, по `file://` браузер их заблокирует.

## Экраны и хеш-адреса

| Адрес                   | Экран                                                        |
| ----------------------- | ------------------------------------------------------------ |
| `#start`                | Стартовый экран: стена фотографий, свечение                   |
| `#auth`                 | Sign Up / Log In, показать пароль                             |
| `#setup1`               | Регистрация, шаг 1: имя, гражданство, местоположение          |
| `#setup2`               | Регистрация, шаг 2: фотографии, описание, соцсети             |
| `#profile`              | Профиль: вкладки Video / Photos, сетка, просмотрщик фотографий |
| `#profileReels`         | Ролики профиля                                                |
| `#feed`                 | Лента видео                                                   |
| `#projects`             | Проекты: три вкладки, карточки, закладки, экран проекта       |
| `#notifications`        | Уведомления                                                   |
| `#notificationClip`     | Ролик, открытый из уведомления                                |
| `#notificationProject`  | Проект, открытый из уведомления                               |
| `#messages`             | Мессенджер: список чатов и переписка                          |
| `#settings`             | Настройки                                                     |

Каждый экран — отдельная запись в history, поэтому системный свайп «назад» в iOS Safari
и кнопка «назад» в Android возвращают на предыдущий экран приложения.

## Структура

```
index.html          разметка всех экранов внутри #app
manifest.json       PWA-манифест: standalone, чёрная тема
404.html            редирект на index.html (GitHub Pages)
.nojekyll           чтобы Pages не съедал папки с подчёркиванием
css/
  base.css          токены, сброс, шрифты, кнопки, поля, нижнее меню
  start.css         стартовый экран
  auth.css          Sign Up / Log In
  setup.css         регистрация и выбор страны
  feed.css          лента видео и ролики автора
  messenger.css     мессенджер
  notifications.css уведомления
  profile.css       профиль и просмотрщик фотографий
  settings.css      настройки
  projects.css      проекты
  layers.css        слои, привязанные к окну (подключается последним)
js/
  app.js            точка входа: порядок загрузки модулей и старт
  core/router.js    экраны, history, хеш-адреса
  core/state.js     состояние, общее для нескольких экранов
  data/             каталоги фотографий и видео
  ui/               шторка выбора, просмотрщик фото, видео, клавиатура,
                    размеры окна, смахивание для закрытия
  screens/          по модулю на экран
assets/
  fonts/            Geist в woff2
  icons/            иконки интерфейса и иконки приложения
  data/authors.json офлайн-фолбэк для аватарок
```

Порядок подключения CSS важен: файлы перечислены в `index.html` в том же порядке,
в каком правила шли в исходном `styles.css`.

## Как это устроено

**Размеры.** `#app` — `position: fixed; inset: 0; height: 100dvh; max-width: 480px`.
Для старых Safari без `dvh` есть фолбэк `--vh`, его пишет `js/ui/viewport.js`.
Вырез и home indicator учитываются через `env(safe-area-inset-*)`: шапки экранов
получают `--head-pad-top`, нижнее меню растёт на `--safe-bottom`.
На экранах уже 360px боковые отступы уменьшаются с 26 до 18px.
На планшете и десктопе — та же мобильная колонка по центру, по бокам чёрный фон.

**Скролл.** Длинные экраны — профиль, лента проектов, экран проекта, уведомления
и настройки — скроллит сам документ. Это принципиально: Safari сворачивает свою
нижнюю панель только когда двигается корневой скроллер, а не контейнер внутри
страницы. Полноэкранные экраны (старт, регистрация, лента видео, ролики,
мессенджер) занимают ровно окно и листаются сами — на них `core/router.js`
ставит на `<html>` класс `is-locked`, который блокирует документ. Шапки, нижнее
меню и полноэкранные просмотры вынесены в `css/layers.css` — он подключается
последним и делает их `position: fixed`, не давая расползтись шире колонки.

**Жесты.** Горизонтальные пейджеры (вкладки Video/Photos, ролики автора в ленте,
ролики профиля) и вертикальная лента видео — нативный `scroll-snap`.
Индикаторы (розовая полоска вкладок, точки в ленте) двигаются по событию `scroll`
контейнера. На всех скроллерах `overscroll-behavior: contain`, на корне
`overscroll-behavior-y: none` — страница не «оттягивается» и не срабатывает
pull-to-refresh. От указателя осталось только то, что скроллом не выражается:
долгое нажатие ставит ролик на паузу, свайп вниз закрывает ролики профиля,
свайп от левого края возвращает назад.

**Клавиатура.** `js/ui/keyboard.js` считает высоту клавиатуры по `visualViewport`
и пишет её в `--kb`. Композер мессенджера поднимается на `translateY(calc(var(--kb) * -1px))`,
лента сообщений получает такой же `padding-bottom` и доскроллвается к последнему
сообщению. `#app` зафиксирован, поэтому страница не уезжает. Отправка сообщения
не забирает фокус у поля — клавиатура остаётся открытой. У всех полей ввода
`font-size` не меньше 16px, иначе Safari зумит страницу при фокусе.

**Видео.** Все ролики `muted`, `playsinline`, с постером. Играет только активный;
запуск идёт через `js/ui/video.js`, который ловит отказ браузера в автозапуске
и показывает постер с кнопкой play. Одновременно «живыми» держатся не больше трёх
элементов `video` — у остальных снимается `src` и вызывается `load()`.

**Пути.** Все ссылки относительные, без ведущего слэша, — приложение работает
из подпапки вида `https://mlkdesign.github.io/kolaba-web/`.

## Данные

Видео и фотографии — прямые ссылки на Pexels, аватарки — Random User API
с офлайн-фолбэком на `assets/data/authors.json`. Прототип наполняется случайными
данными при каждой загрузке.
